# 受控模型作业

普通 agent turn、辅助模型调用和宿主独立模型任务共用 Core 的输入检查、输出上限、usage reservation 与执行取消契约。SDK 的官方 HTTP model plugin 负责 HTTP/协议；宿主只提供配置、身份、授权后的路由和凭据恢复策略。

`ModelJobClient` 是独立任务的公共入口。`ChatModelJob` 携带 connection、model、request、RunLimits、stage、max_calls 和可选 repair/workflow。`ModelJobRepair::validate` 可返回新的公共 ChatRequest；SDK 在同一 run、取消控制和 usage ledger 中执行下一次，更新 messages/tools/options/extensions，不重置总预算。`ModelWorkflow` 支持 memory 等公共插件组合多个受控调用。

`start` 返回 handle；等待前取可克隆的 `control()` 以便在 `wait` 执行期间取消。handle 可读取事件和 dispatch 次数。`execute` 的 future 被丢弃也取消其所属 run。`close` 拒绝新任务并取消、等待全部活动工作。`LazyModelJobClient` 将首次创建和 close 串行化，close-before-first-use 也永久拒绝后续请求。

`embed`、`rerank` 和 `rerank_observed` 提交 typed operation，复用 run 预算、超时和生命周期；observed 结果包含聚合 usage 与尝试数。RerankModel 的默认 `rerank_with_usage` 保持旧适配器兼容，官方 HTTP 实现返回实际 usage；缺失 usage 保留 reservation。主 agent 已预留的单次模型调用不再在宿主套独立 job，以免重复计数。

每次 adapter dispatch 最多发一次模型 HTTP。dispatch 计数是保守预算：配置、序列化或加密等发送前失败也可能消耗一个 dispatch slot，因此一般契约是 HTTP 次数不超过 dispatch 数；有效 TCP fixture 中两者相等。Provider 不得隐藏 401 重发、流为空补发或通用重试。SDK 在未输出时处理 transient 重试和显式一次认证恢复，受同一 max_calls/RunLimits 约束；400/权限/额度/账号变化不进入通用重试，输出后失败与超时为 indeterminate。

模型最终输出 token limit 使用 Core 裁定值。SDK 预算含图像、工具 JSON、prepared schema、Responses continuation 和 rerank framing；缺失 provider usage 不退款为零。产品仍可显示 usage unavailable，而 run ledger 使用保守 reservation。

memory 插件的 `MemoryCompactor` 复用 context ModelCompressor，通过 invoke_auxiliary 完成分段压缩；`MemoryCompactionResult` 返回 summary、本次 ledger 差额 `usage` 和可空的 `provider_usage`；前者用于预算计费，后者用于产品 actual audit。缺失 usage 或 ledger 含未报告的失败尝试时 provider_usage=None，不把保守计费伪造为实际 usage，也不重复记此前主 run。分块短期记忆和 revision/CAS 接口见 memory crate 文档。

回归入口：Framework `tests/model_jobs.rs`；官方 HTTP `tests/protocol_boundary.rs`、`tests/personai_transport.rs`；memory `tests/compaction.rs` / `tests/short_term.rs`。真实 TCP 回归在 runtime teardown 前断言取消、超时、close、协议失败和溢出后的连接 active=0。

模型 HTTP client 通过 SDK `ModelHttpClient::from_builder` 保留宿主 proxy/connect/pool/timeout 配置并强制禁止自动 redirect；307/308 是终态错误，配置应使用实际模型 endpoint，不能隐式再次 POST。PersonAI 官方 gateway request 加密与 header 仍保留。
