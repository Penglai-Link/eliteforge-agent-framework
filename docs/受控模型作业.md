# 直接模型调用

普通 agent turn、辅助模型调用和宿主独立模型调用共用 Core 的输入检查、输出上限、usage reservation 与取消契约。官方 HTTP model plugin 负责 HTTP/协议；宿主提供配置、身份、经授权的真实模型路由和凭据恢复策略。

独立文本、embedding 和 rerank 使用已有 `ModelClient` 与 `ModelOperations`；多次摘要调用使用已有 `ModelWorkflow` / `ChatExecutor`。这些调用不构建 Agent，不调用 Agent `start/run`，不注册原生 run，不创建 session、历史或工具循环。`ContextReductionJob` 继续作为既有 context Hook 返回的 reduction plan 数据结构；远端图片/视频的真实异步 job 协议也继续保留。

## 注册与调用

`ModelClient::new(ModelRuntimeUpdate)` 校验已授权的 chat、embedding、rerank 注册；`ModelClient::from_runtime(Arc<ModelRuntime>)` 接受已有运行时。`with_runtime` 创建固定绑定视图，`with_options` 配置控制数据；两者共享原客户端的停止与 drain owner，切换目录不能复活已关闭客户端。宿主先完成 ACL 与凭据绑定，才注册真实 `ModelRef` 和 descriptor。

正式直接调用入口为：

- `chat` / `chat_observed(&ModelRef, ChatRequest, &RunLimits, stage)`。
- `chat_with_validator_observed` 额外接受 `Arc<dyn ModelResponseValidator>`；验证器返回新的公共 `ChatRequest` 时继续执行，更新 messages/tools/options/extensions，共享总调用上限与 ledger。
- `workflow_observed(&ModelRef, Arc<dyn ModelWorkflow>, &RunLimits, stage)`；workflow 通过传入的 `ChatExecutor` 调用模型。
- `embed_observed(EmbeddingRequest, &RunLimits)` 与 `rerank_observed(RerankRequest, &RunLimits)`；已有 `ModelOperations` typed 方法继续可用。

例如，宿主完成模型注册后直接调用：

```rust,ignore
let client = ModelClient::new(update)?;
let options = ModelInvocationOptions::for_call(&limits)?;
let cancellation = options.cancellation.clone();
let observed = client.with_options(options)
    .chat_observed(&model, request, &limits, "title").await;
// 另一个控制任务可调用 cancellation.cancel()。
let response = observed.into_result()?;
client.close().await;
```

`ModelInvocationOptions::for_call(&RunLimits)` 只创建 ledger、deadline、取消及 extensions 等控制数据。`for_run(&RunContext, &RunLimits)` 复用父调用的 ledger、取消、原 deadline 和树级 continuation 限额；goal judge、repair 与摘要不另建原生 child run。业务传入的限制只能收紧有效父限制；`RunLimits.max_model_calls_per_step` 与 `ModelInvoker::with_call_limit` 约束整个 workflow/validator scope 的派发数。替换请求 extensions 不能重置父预算。

## 取消、关闭与协议边界

取消 options token、丢弃调用 future 或宿主 `stop()` 会停止相应 HTTP 工作。`drain().await` 等待本 owner 的活动调用退出；`close` / `close_observed` 先停止准入再 drain。首次使用前关闭也拒绝后续调用，所有克隆和固定绑定视图遵循相同关闭状态。

每次 adapter dispatch 最多发一次模型 HTTP。dispatch 是保守发送预算：配置、序列化或加密等发送前失败也可能消耗 slot，因此 HTTP 次数不超过 dispatch 数；有效 TCP fixture 中两者相等。Provider 不隐藏 401 重发、空流补发或通用重试。SDK 仅在未输出时处理 transient 重试和显式一次认证恢复，受同一调用/时间/总 token 上限约束；400、权限、额度、账号变化不进入通用重试，输出后失败与超时为 indeterminate。

HTTP client 通过 `ModelHttpClient::from_builder` 保留宿主 proxy/connect/pool/timeout 配置并禁止自动 redirect；307/308 为终态错误，应配置实际 endpoint，不能隐式再次 POST。PersonAI 官方 gateway request 加密与 header 保持原协议。

## 预算与观察

最终输出 token limit 使用 Core 裁定值。SDK 预算包含图像、工具 JSON、prepared schema、Responses continuation 和 rerank framing；缺失 provider usage 不退款为零。`ObservedModelResult` 的成功和错误都带 `ModelExecutionReport`：dispatch、attempt/retry、选择、保守 ledger、完整 provider usage 或已知 subtotal。未知用量不能伪造为实际费用；cached/reasoning 指标只在各段完整报告时聚合。

`MemoryCompactor` 复用 context `ModelCompressor`，经 `invoke_auxiliary` 完成分段压缩。`MemoryCompactionResult.usage` 是本次 ledger 差额，`provider_usage` 是可空 actual audit；缺失 usage 或包含未报告失败尝试时保持 unavailable，既不伪造实际计费，也不重复计此前父调用。分块短期记忆与 revision/CAS 接口见 memory crate 文档。
