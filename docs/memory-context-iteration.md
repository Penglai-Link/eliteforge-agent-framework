## 目标与范围

把当前只管理会话消息的 `Memory` 改为会话存储抽象，补齐统一的上下文窗口、分块预算、
压缩和结果转存机制。ReAct、串行工作流和 DAG 使用同一个上下文组装入口。

Framework 提供通用抽象与默认执行机制，配套 Plugin 提供存储、摘要、检索等实现。
Tron 负责适配自己的数据、权限和业务规则。本轮不修改 Tron 的业务代码。

## 已确定的设计

### 记忆、存储与窗口

| 概念 | 职责 |
|---|---|
| 短期记忆 | 当前会话和任务的信息，包括消息、摘要、目标、Todo 和工具结果 |
| 长期记忆 | 跨会话保存、检索、更新和删除的记忆条目 |
| 会话存储 | 保存结构化消息；提供历史读取和追加能力 |
| 上下文窗口 | 某次模型调用实际使用的内容，受该模型容量限制 |
| 工作流状态 | 保存执行位置、待执行调用、审批及恢复信息 |
| 附件存储 | 保存大结果原文，通过引用读取 |

短期记忆可以大于上下文窗口。裁剪和压缩模型输入不删除源消息。
会话摘要不自动转为长期记忆；长期记忆写入使用单独的策略。

### 抽象调整

| 当前类型或能力 | 拟调整为 | 职责 |
|---|---|---|
| `Memory` | `ConversationStore` | 按会话保存和读取结构化消息 |
| `MemorySession` | `ConversationSession` | 一次运行使用的会话读写对象 |
| `InMemoryMemory` | `SqliteConversationStore` | 默认存储改为 SQLite，无内存回退 |
| `MemoryPlugin` | `ConversationStorePlugin` | 注册会话存储；同步调整服务包装类型 |
| `ContextFragment` | `ContextBlock` | 带稳定 ID、来源、结构化内容和信任级别的上下文块 |
| `ContextContributor` | 保留并调整输入、输出 | 按块提供上下文内容 |
| 分散在 `ModelInvoker` 中的组装逻辑 | `ContextAssembler` | 统一获取、处理和排列上下文块 |
| 当前总量与片段筛选逻辑 | `ContextBudgetPolicy` | 分配块额度并校验总预算 |
| `ContextReducer` | 调整为按块处理 | 在指定额度内裁剪、筛选或压缩该块 |
| 无 | `ContextWindow` | 保存组装后的模型输入和组装报告 |

`prepare`、`prepare_for_model` 中的窗口裁剪职责移到上下文管理层。会话存储负责消息和版本，
不负责选择当前模型的预算算法。`MemoryOutcome` 等关联命名同步整理。

长期记忆的检索、写入、更新、删除由独立的 `LongTermMemory` 接口提供。
不再用一个 `Memory` trait 同时承载会话追加、检索、工作状态更新和窗口压缩。

### 默认预算与压缩策略

| 项目 | 默认行为 |
|---|---|
| 块预算 | 各块独立配置 Token 额度；可用绝对上限或窗口比例表达，两者同时配置时取较小值 |
| 总量 | 扣除输出预留和协议开销后，校验各块分配额度之和；配置超额则报错 |
| 压缩 | 每个块选择自己的 `ContextReducer`，只处理本块 |
| 剩余额度 | 不在块之间借用或重新分配 |
| 优先保留 | 不提供优先级、抢占或最低额度优先分配逻辑 |
| 联合压缩 | 默认实现不提供多个块联合压缩 |
| 处理失败 | 必要块报错；只有明确配置为可省略的块才允许省略，并记录原因 |
| 最终顺序 | 按显式配置的块顺序拼接；块内保留合法的消息顺序 |

“允许省略”是失败处理配置，不参与预算竞争。默认策略不根据顺序给前面的块多分额度。
压缩返回后重新估算和校验；仍超限时不能直接发送。

自定义 `ContextBudgetPolicy`、`ContextReducer` 或 `ContextAssembler` 可以扩展复杂策略；
本轮不实现借用、优先保留和跨块联合压缩。

### 调用流程

```text
选择本次模型
  → 确定输入容量、输出预留和估算器
  → 获取会话快照与块配置，分配各块预算
  → Contributor 按额度获取内容
  → 各块独立裁剪或压缩
  → 按配置顺序组装 ContextWindow
  → 模型中间件
  → 最终结构、容量和工具授权校验
  → 模型调用
```

默认顺序可以是：系统指令 → 检索记忆 → 会话摘要 → 工作状态 → 最近会话。
最近会话包含当前输入和工具交互，避免重复插入当前输入。应用可以调整顺序。
Contributor 并行完成的先后不改变最终排列；工具定义仍通过模型请求的工具字段传递。

### 工具调用、历史与附件

```text
工具返回完整结果
  → 工具结果转存中间件
     ├─ 小结果：原样返回
     └─ 大结果：保存原文，返回预览和附件引用
  → Loop 保存结构化调用与处理后的结果
  → ContextAssembler 读取历史，不自动展开附件
  → 模型需要详情时调用附件读取工具
```

历史保留调用 ID、工具名、JSON 参数、结果状态、内容及结果引用。
附件保存完整原始结果；读取片段作为新的工具结果进入历史。

模型输出的协议续接数据、工具调用与结果配对必须保留。历史消息和附件共同构成可追溯记录，
不要求大结果全文重复写入会话存储。

## 迭代前的缺口

| 位置 | 当前行为 | 本轮改动 |
|---|---|---|
| ReAct | 通过 `MemorySession.append` 保存完整工具交互批次 | 迁移至会话存储抽象，保留结构化数据 |
| WorkflowLoop | 使用 `Checkpoint.transcript`，不经过注册的 `Memory` | 统一历史读取抽象与组装入口，保留检查点提交的一致性 |
| DAG 内置 ReAct | 历史位于节点的嵌入式工作流检查点 | 提供节点、分支对应的历史视图 |
| 自定义节点 | 任意工具调用不会自动生成会话消息 | 明确记录入口，按节点需要写入 |
| 上下文组装 | 历史先使用剩余额度，可选片段再使用余额 | 改为独立块预算与显式顺序 |
| 摘要 | `ModelCompressor` 返回临时投影 | 增加摘要保存、来源范围和复用机制 |
| 最终结构化输出 | `structured` 保存在运行结果或工作流状态中 | 补齐会话消息中的结构化输出记录 |
| 大结果转存 | 仅检查并替换 `content`，保留全部 `structured` | 同时考虑内容和结构化大数据，定义明确结果引用 |

## 实施阶段

### 1. 会话存储与记录格式

- 完成 `Memory` 系列类型、注册入口、错误及文档命名迁移。
- 明确消息 ID、会话和分支标识、版本、完整批次追加以及历史快照的语义。
- 保留工具参数、调用关联、结构化结果、错误状态和模型协议数据。
- 增加模型最终结构化输出的历史字段，旧消息反序列化采用兼容默认值。
- 将模型输入裁剪从存储职责中移出，更新内存实现及仓库内调用方。

验收：会话可以完整读回文本、媒体、工具交互和结构化输出；取消或压缩不会破坏已保存历史。
原有检查点能够读取；涉及持久化格式变化时提供版本识别和迁移规则。

### 2. 上下文窗口与默认组装器

- 定义 `ContextBlock`、`ContextWindow`、`ContextAssembler`、`ContextBudgetPolicy`。
- 调整 `ContextContributor` 输入，提供当前请求、阶段、模型、块额度及只读历史视图。
- 配套 Plugin 入口分别注册组装器、预算策略、Contributor 和块处理配置。
- 默认组装器使用独立块额度和显式顺序；为普通对话提供无需配置块的简单默认组合。
- 明确模型窗口、输入上限和输出预留的计算口径，避免重复扣除输出预留。
- 统一文本、媒体、工具 Schema、输出 Schema 和协议数据的估算；模型切换后重新组装与校验。
- 对 Contributor 设置读取量、返回量、超时和取消边界。

验收：顺序稳定；额度不跨块流动；总配置超额明确失败；异步完成顺序不影响提示词顺序。
切换到更小窗口模型时重新计算，不直接复用不兼容输入。

### 3. 按块处理与持久化摘要

- 调整 `ContextReducer`，接收该块内容、额度、目标模型估算信息和调用上下文。
- 提供原样保留并校验、保留完整近期轮次、条目选择和模型摘要等默认处理实现。
- 明确不可拆分的消息单元；工具调用与结果、模型签名数据不能随意截断。
- 摘要记录会话、分支、源消息范围、源版本和策略版本，支持有效摘要复用。
- 默认摘要以独立历史块为处理对象；不实现“摘要块与另一个历史块联合压缩”。
- 摘要模型通过辅助调用入口使用同一运行预算、中间件、取消和观测；禁止递归触发自身压缩。
- 对摘要调用次数、成本和失败处理设限；生成后检查是否缩小且满足额度。

验收：源消息不变；摘要不会重复覆盖同一历史范围；失败处理可解释；摘要调用不绕过预算。
历史数据和检索结果经压缩后仍是数据，不升级为系统指令。

### 4. 工具结果转存

- 将 `content` 和 `structured` 都纳入大结果判定，避免结构化数据绕过转存。
- 定义原文、模型可见预览、结构化结果引用及运行控制信息的表示方式。
- 原文成功写入附件存储后再发布引用；保留调用关联、错误标记和必要运行控制信息。
- 提供原始结构化结果的显式读取方式，更新依赖完整结果的调用方。
- 限制附件读取片段大小，配置读取工具排除转存，避免循环转存。
- 明确附件访问范围、保留时间、失效响应及未被历史引用附件的清理方式。
- 工具已执行后的转存或历史写入失败，不触发自动重跑工具。

验收：大文本和大 JSON 都能转存；附件可还原完整结果；历史不重复内联大数据。
覆盖转存失败、会话写入失败、取消、恢复及附件不存在的情况。

### 5. 各类 Loop 接入与恢复

- ReAct、WorkflowLoop 和 DAG 内置 ReAct 统一调用 `ContextAssembler`。
- 工作流历史可使用检查点支持的会话视图，不强制另外双写独立存储。
- 如果需要外部会话副本，明确提交、幂等同步和恢复方式，不能用两次独立写入假装原子提交。
- 并行节点按会话分支或历史版本隔离摘要写入；使用版本检查避免覆盖新结果。
- 恢复时区分执行检查点、会话历史和上下文派生缓存，明确快照复用与重新加载规则。
- 提供自定义节点记录会话交互的入口；纯计算节点仍可不使用会话存储。

验收：同样的块配置在三类执行器中生效；节点历史不会串用；恢复不丢失已确认记录、不重复执行已确认工具。
后续交互迭代已将 ReAct 接入同一持久化执行实现，支持问答、审批及崩溃恢复；
当前行为见[用户问答与工具审批](interactions.md)。

### 6. 长期记忆 Plugin 与短期记忆组件

- 整理会话存储、摘要、工作状态 Contributor 的组合方式，形成短期记忆使用示例。
- 定义长期记忆的检索、写入、更新和删除接口，以及带来源、版本和有效期的条目。
- 提供基础存储实现、检索 Contributor 和记忆工具；具体后端在本阶段选择并说明能力边界。
- 记忆写入与自动事实提取分开，首版不默认开启自动提取。
- 处理重复、纠正、删除和失效；派生缓存按来源版本失效。
- Tron 现有搜索、保存、删除服务可以通过适配接入；框架不引入用户空间、工作域等业务枚举。

验收：长期记忆可以跨会话读取；检索结果按独立块额度进入窗口；删除后不再通过旧缓存注入。
接口预留不同检索后端，不要求首版实现完整向量检索、混合排序或复杂记忆治理。

### 7. 观测、示例与文档

- 组装报告记录每块原始估算、分配额度、最终估算、顺序、源版本和处理原因。
- 默认不导出正文；错误报告沿用可脱敏的结构化错误机制。
- 保持现有 run、节点、模型和工具 span 关联，区分摘要辅助调用和主模型调用。
- 中间件改写请求后再次校验，区分组装时的报告和最终发送统计。
- 更新架构与插件表，统一“扩展接口、默认行为、框架提供的默认实现”的写法。
- 保留最小 Agent 示例，增加分块预算、流式消费、摘要复用和附件读取的简单例子。

验收：能解释某块为何被压缩、省略或导致失败；示例可编译，离线验证不需要真实模型账号。

## 验证与交付

每个阶段交付代码、相关文档和针对性测试。重点覆盖独立预算、排列顺序、消息完整性、
大结果引用、并行版本冲突、失败与恢复，不为类型改名增加重复行为测试。

最终运行工作区测试、文档测试、Clippy 和格式检查，并使用本地模型协议 fixture 验证调用链。
真实供应商验证单独记录；不将未执行的 Anthropic 测试写为通过。

执行顺序：1 → 2 → 3 → 4 → 5 → 6 → 7。观测和文档随各阶段更新，最后统一验收。
本计划不包含 Tron 业务迁移、UI 实现、插件热加载或分布式记忆协调。
