# 会话与目标存储

Framework 管 Session、Goal、Run、Event、历史、检查点、交互和摘要。应用管用户权限、工作空间、业务关联和界面。两边共用数据库运行时，通过表名区分归属。

```text
Tron 权限 / 业务关联 / UI
             │ Framework API
             ▼
Framework    Session
               ├─ Goals + 判定记录
               ├─ Runs + 父子关系
               ├─ Events
               └─ 历史 / 检查点 / 交互 / 摘要 / 上下文
             │ 存储契约 + TransactionManager
             ▼
storage-local：SqliteDatabase，一条受控连接
             │
             ▼
application.db
  ef_*       Framework 表
  tron_*     应用业务表（应用自行命名）
```

这是开发阶段的新 schema。重建开发数据库，不迁移历史数据，也不提供旧 API 的兼容层。Tron 的适配后续从 master 新建分支进行。

## 装配

应用打开 `SqliteDatabase`，注入存储插件和自己的业务仓库。Framework 全局安装一个存储实现，Agent 只选择 loop、模型和工具。

```rust,ignore
let database = SqliteDatabase::open("tron.db").await?;
let framework = Framework::builder()
    .plugin(LocalStoragePlugin::new("tron.db", "artifacts")
        .with_database(database.clone()))
    .plugin(AgentLoopPlugin::named("react", ReactAgentLoop))
    .plugin(GoalPlugin)
    .defaults(AgentSelection {
        agent_loop: Some("react".into()),
        ..Default::default()
    })
    // 在这里安装应用使用的模型、工具和其他能力。
    .build().await?;
```

`artifacts` 目录由应用提前创建并保护；Unix 权限为 0700。注入的数据库由应用最终关闭，Framework 关闭后业务仓库仍能使用它。

## 共享事务

```rust,ignore
let sessions = framework.sessions()?;
let goals = framework.goals()?;
let session = framework.transaction(async {
    let session = sessions.create(SessionRecord::new("研究任务")).await?;
    goals.set(GoalRecord::new(&session.id, "完成研究并提供证据")).await?;

    let id = session.id.clone();
    database.call(move |connection| {
        connection.execute(
            "INSERT INTO tron_session_links(framework_session_id) VALUES (?1)",
            [id],
        )
    }).await.map_err(|_| StateError::Backend("写入业务关联失败".into()))?;
    Ok(session)
}).await?;
```

这三项写入在同一个事务里。内层自动加入，最外层决定提交或回滚；内层失败被捕获后，事务仍会回滚。取消时先完成回滚，再释放连接。

同一个数据库文件不等于同一个事务。业务仓库必须使用同一个 `SqliteDatabase` 实例，不能再单独建连接池。事务上下文跟随当前 Tokio task，`spawn` 的任务不继承它；不要在事务里等待另一个 task 使用数据库，也不要把整个 Agent 运行或远程调用包进数据库事务。

## Session 和 Goal

`framework.sessions()` 提供创建、查询、分页、CAS 更新、归档、恢复、删除、上下文读写和 artifact 引用。Session 归档时拒绝正在运行的执行和有效租约。

Framework 的 Session ID 在数据库内全局唯一，没有 `workspace_id` 字段，也不负责工作空间授权。Tron 在业务表中保存 `workspace_id → framework_session_id` 的关联。工作空间会话列表从关联表筛选；读取、修改、运行、访问 Goal / Run / Event 和删除前，Tron 都先校验该 Session 属于当前工作空间且用户有权限。Framework 的 `sessions.list()` 是全局内部查询，不能直接用作面向用户的工作空间列表。子会话通过执行归属关联到根 Session，授权沿根 Session 的业务关联校验。

创建会话和写入工作空间关联使用同一个共享事务；删除会话及关联也一样。如果业务关联表使用外键引用 `ef_sessions`，可以设为 `ON DELETE CASCADE`；使用限制删除的外键时，在事务里先删除业务关联，再删除 Framework 会话，后者失败会把关联删除一起回滚。工作空间隔离不要求每个工作空间使用独立数据库或独立 Framework 存储插件。

`framework.goals()` 提供设置、查询、更新、状态转换和判定。每个 Session 最多有一个未结束 Goal；完成、取消或清除后的记录保留为历史，可以再设置新目标。所有修改使用 revision 防止旧请求覆盖新状态。

Goal 状态为 `ACTIVE / PAUSED / BLOCKED / COMPLETED / CANCELLED / CLEARED`。判定为 `CONTINUE / COMPLETED / BLOCKED / NEEDS_USER_INPUT`。判定同时保存进度、原因、下一轮输入和对应 Run，每个 Run 只能判定一次；判定依据必须是该 Goal 已完成的真实 Run。

```rust,ignore
let goal = goals.active(&session.id).await?.unwrap();
let paused = goals.transition(
    &goal.id, goal.revision, GoalStatus::Paused, Some("用户暂停".into()),
).await?;
let resumed = goals.transition(
    &paused.id, paused.revision, GoalStatus::Active, None,
).await?;
```

## 执行和延续

```rust,ignore
let agent = framework.agent(Default::default()).build().await?;
let mut request = RunRequest::new(&session.id, "开始研究");
request.limits.max_model_calls_per_step = Some(3);
let result = agent.run_to_goal(
    request, &resumed.id, Arc::new(ModelGoalPolicy::default()),
).await?;
let goal = goals.get(&resumed.id).await?;
```

`run_to_goal` 先运行选定的 Agent，再由 Framework 判定是否继续。执行可使用 ReAct、Workflow、DAG 或 External；判定器通过 `GoalPolicy` 替换。`ModelGoalPolicy` 使用原有受控模型调用管线。

延续驱动器和每个子执行仍属于同一个逻辑 Session，使用不同 execution scope，分别保存检查点和运行状态。Goal 的 ReAct 子执行继续写主对话分支；普通委派子执行默认使用自己的分支。父子 Run 和 root Run 都持久化，查询不需要选择业务 Agent。

每轮共享初始执行的总 token、步骤、工具调用、模型调用和绝对截止时间，不会按轮数重新发预算。调用前必须设置 `max_model_calls_per_step`。另外受 Goal 的 `max_runs` 限制。反复给出相同输入和进度、达到运行上限、连续三次判定失败都会暂停。任务需要交互、失败、取消或耗尽预算时也暂停 Goal；删除等待中的调用 future 会取消当前拥有的执行。

`RunResult` 是最后一次执行的结果，是否达到目标以持久化的 Goal 状态为准。

## 查询、恢复和删除

`framework.runs().list(session_id)` 返回会话及其所属子会话的运行记录。`framework.events().list(session_id, after_sequence, limit)` 提供按会话顺序读取的持久事件，包含会话修改、目标判定、运行状态和异步执行事件。检查点内的 journal 同步落库；流式输出片段仍通过现有实时输出通道传递，最终结果保存在 Run 中。

启动时把租约过期但仍标记运行中的 Run 改为 `RECOVERY_REQUIRED`，暂停所属 Goal，等待显式处理；不会自动重放工具或 External 执行的副作用。

```rust,ignore
framework.transaction(async {
    // 用同一个 database 句柄先删除应用自己的业务关联。
    sessions.delete(&session.id).await?;
    Ok(())
}).await?;
```

删除会清理全部 scope、所属子会话、Goal、判定事件、Run、交互、历史、摘要和上下文。有效运行及租约返回 `Busy`。同 ID 的迟到写入会被 admission tombstone 拒绝。应用负责授权和停止自己的后台任务。

Session 独占 artifact 在最后一个引用删除时清除元数据，数据库提交后清理文件。清理失败记录日志并保留重试队列，不让文件错误撤销数据库删除。跨 Session 的引用仍保留文件；共享长期记忆和模型目录由各自的生命周期管理。
