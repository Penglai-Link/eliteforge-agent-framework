# 远程访问规范

远程访问让同一局域网或经 FRP/反向代理的移动端连上桌面产品。桌面端本身走 loopback，不需要令牌；其他来源必须开启远程访问并出示配对令牌。

## 产品编码与节点

- 每个产品有自己的产品编码（Tron 为 `tron`），随配对信息、身份接口和请求头 `X-Product-Code` 一起传递。不要复用别的产品的编码，否则移动端会连到错误的产品。
- 节点 ID 标识一台已配对的电脑。移动端的流程是「产品 → 节点 → 会话」：先按产品编码找到节点列表，再按节点 ID 建立会话。
- 同一台电脑只应存在一个有效节点标识；重装或重置配置后重新配对，不要伪造或猜测节点 ID。
- 配对信息包含访问地址、产品、节点和「是否已配置令牌」。这些可以展示；令牌不能。

## 地址与 HTTPS

- 生产环境必须通过 HTTPS 访问。TLS 由 FRP、反向代理或网关终止，转发到远程端口时应带上 `X-Forwarded-Proto: https`，让后端按 HTTPS 处理。
- 仅允许在可信局域网内显式开启明文 HTTP，并保持默认拒绝。移动端和浏览器不要长期使用明文地址。
- 远程访问使用独立端口（默认主端口 + 1）。FRP 或反向代理必须转发到这个远程端口，不要只转发桌面端 loopback 使用的主端口，否则隧道请求会绕过配对令牌。
- 对外地址填写公网域名或 FRP 入口；局域网内可留空由程序探测。地址只支持 `http://` 或 `https://`，不要带路径、查询串或片段。

## 令牌与 JWT

- 配对令牌是远程端点的唯一门槛，只在本机设置页或二维码中出现。后端对非 loopback 请求校验令牌。
- 移动端拿到的是短期 JWT，不是长期配对令牌。JWT 有效期应尽量短，并在过期前用配对凭据续期；不要把 JWT 持久化到不安全的位置，也不要写入日志、会话历史或遥测。
- 令牌比较必须使用恒定时间比较，错误信息不能回显令牌或它的部分内容。
- 令牌轮换后，所有既有客户端的配对立即失效，需要重新扫码或重新输入令牌。轮换前先告知用户影响范围；不要在高频操作中自动轮换。
- 令牌为空时，远程端点应拒绝服务并提示先在桌面端启用远程访问，不能用空令牌放行。

## Agent 的边界

- Agent 只能通过 `remote_access` 工具查看状态和配对信息，或执行轮换、启停。`rotate`、`enable`、`disable` 必须先获得用户明确同意，并传 `confirm: true`；没有确认时不要重试或绕过。
- 工具返回的配对信息只有地址、产品、节点和是否已配置，以及「请在桌面端设置页查看配对二维码/令牌」。不要要求工具打印令牌，也不要从状态、日志、配置或二维码内容中读取令牌。
- 不要在回复、代码块、截图说明或链接中输出令牌、带令牌的配对 URI、JWT 或它们的片段。用户需要令牌时，引导其打开桌面端设置页或扫描二维码。
- 工具报错时按原样说明原因（例如未开启、令牌缺失、配置写入失败），不要自行修改配置文件或重启服务来「修复」。

## 排查顺序

1. 用 `remote_access` 的 `status` 确认远程访问已启用、监听器已生效、令牌已配置；需要重启才生效时明确告知用户。
2. 确认访问地址与端口和实际监听一致；经 FRP/代理时确认转发的是远程端口。
3. 用 `pairing` 核对产品编码、节点和地址；令牌缺失或轮换后，让用户重新扫码配对，不要索取令牌。
4. 手机仍失败时，检查 HTTPS、证书、`X-Forwarded-Proto`、防火墙和代理白名单；只在可信局域网才考虑显式允许明文 HTTP。
5. 需要更换令牌时，先说明既有客户端会掉线，再在用户确认后执行 `rotate`；成功后提醒用户重新配对。
